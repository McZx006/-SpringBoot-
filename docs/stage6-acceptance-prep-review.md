# 第六阶段联调与验收准备审核清单

## 1. 本阶段目标

本阶段不再扩新业务模块，重点提升“已有功能的可验收性”，把后台表单校验、服务端业务校验、接口文档和联调材料补到更适合验收的状态。

## 2. 本阶段新增内容

### 前端后台表单校验

| 页面 | 新增内容 |
|---|---|
| 学员/资料/试卷管理 | 新增必填校验、手机号邮箱格式校验、时长/总分校验 |
| 试题管理 | 新增解析必填、题型选项数量校验、答案格式校验 |
| 留言/公告/轮播图/论坛管理 | 新增内容必填校验 |

### 后端服务端校验

| 模块 | 新增内容 |
|---|---|
| 学员管理 | 学号不能为空、姓名不能为空、学号唯一、手机号/邮箱格式校验 |
| 资料类型 | 类型名不能为空、类型名唯一 |
| 学习资料 | 名称、简介、类型必填，文件地址和视频地址至少有一个 |
| 试卷 | 名称、说明、时长、总分必填且数值有效 |
| 试题 | 题目、题型、答案、解析必填，按题型校验选项和答案 |
| 考试开始/提交 | 未发布试卷不可开始或提交，空试卷不可进入考试 |

### 文档与联调材料

| 文件 | 作用 |
|---|---|
| `docs/api.md` | 已更新为当前真实接口范围 |
| `docs/run.md` | 已同步当前能力和下一步重点 |
| `docs/integration-checklist.md` | 联调与接口测试清单 |
| `docs/verification-log-template.md` | 真实编译与联调记录模板 |

## 3. 当前最重要的验收收益

1. 后台表单不再只靠前端“能输就发”，而是有了更明确的拦截。
2. 即使绕过前端，后端服务层也会拦住一批明显脏数据。
3. 联调和验收材料已经开始成形，不再只有代码没有过程文档。

## 4. 当前验证进展

1. 后端已在 `backend` 目录使用本地仓库 `.m2repo` 执行 `mvn.cmd --% -Dmaven.repo.local=D:\桌面文件\实训\.m2repo -DskipTests compile`，结果为 `BUILD SUCCESS`。
2. 学员端 `student-web` 已执行 `npm run build` 通过，仅有 Vite/Rollup 体积提示。
3. 管理端 `admin-web` 已执行 `npm run build` 通过，仅有 Webpack 体积提示。

## 5. 当前仍未完成的验收项

1. 后端连接真实 MySQL 后启动验证。
2. 学员端、管理端真实启动联调验证。
3. 登录、资料、考试、论坛、留言、公告、轮播图等主流程逐项接口验证。
4. 联调清单逐项执行后的实际结果填写。

## 6. 建议你本轮重点审核

1. 这种“先补服务端校验，再做真实联调”的推进方式是否接受。
2. 当前后台表单和服务层校验范围是否够用。
3. 文档粒度是否适合你后续提交或汇报使用。

## 7. 审核通过后的下一步建议

如果这一轮通过，下一步建议直接做真实验证：

1. 启动数据库、后端、学员端、管理端。
2. 按 `integration-checklist.md` 逐项联调。
3. 把结果填写到 `verification-log-template.md`。
4. 根据联调结果继续修复接口、页面和权限边界。
